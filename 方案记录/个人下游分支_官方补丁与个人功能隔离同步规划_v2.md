## 1. 目标

本规划用于长期维护以下内容：

- 持续接收 Blender 官方修复和版本更新。
- 保留个人表面焦散、体积焦散、玻璃色散和 DLSS 功能。
- 降低官方更新与个人功能之间的冲突范围。
- 让每次同步、编译、测试和回退都有明确记录。
- 在换电脑后可以完整恢复源码、分支关系和构建方法。

## 3. 分支职责

```text
upstream/blender-5.2
    只跟踪 Blender 官方 5.2 系列提交，不写个人功能

upstream/blender-main
    跟踪官方主线和 Alpha 版本，只用于研究和补丁来源

sync/blender-5.2.x
    单次官方同步的临时分支，处理补丁和冲突

feature/caustics-surface
    表面焦散、光子半径、光子差分

feature/caustics-volume
    丁达尔体积焦散、体积光束、体积查询和性能优化

feature/dispersion
    玻璃色散及焦散路径中的色散传递

feature/dlss-viewport
    DLSS 视口降噪、NGX 生命周期和日志控制

main
    经过编译和固定场景验证的个人发布分支
```

当前仓库只有 `main` 是正式工作分支。后续新功能和官方同步按上述职责逐步建立，避免继续把所有改动直接堆到 `main`。

## 4. 代码隔离原则

### 4.1 独立文件优先

个人新增算法尽量放入独立文件：

```text
intern/cycles/integrator/photon_map.cpp
intern/cycles/integrator/photon_map.h
intern/cycles/kernel/integrator/photon_lookup.h
intern/cycles/kernel/integrator/photon_trace.h
intern/cycles/kernel/integrator/photon_trace_types.h
intern/cycles/integrator/denoiser_dlss.cpp
intern/cycles/integrator/denoiser_dlss.h
build_files/cmake/Modules/FindDLSS.cmake
```

官方文件只保留必要的调用入口、数据传递和开关。算法实现不重复嵌入多个官方路径。

### 4.2 高冲突文件保护

以下文件同时被官方和个人功能频繁修改，合并时必须逐段处理：

```text
intern/cycles/kernel/data_template.h
intern/cycles/kernel/types.h
intern/cycles/scene/integrator.cpp
intern/cycles/kernel/integrator/shade_surface.h
intern/cycles/kernel/integrator/shade_volume.h
intern/cycles/integrator/path_trace.cpp
intern/cycles/session/session.cpp
intern/cycles/blender/addon/properties.py
intern/cycles/blender/addon/ui.py
```

处理规则：

1. 先读取官方目标文件和当前个人文件。
2. 以函数和数据结构为单位合并，不整文件覆盖。
3. 个人字段集中放在带有 `CyclesPlus` 标记的区域。
4. 官方字段保持官方顺序，个人字段追加在个人区域。
5. 每次修改只对应一个官方修复或一个个人需求。
6. 合并后检查 Kernel 结构布局、GPU 对齐和 CUDA/OptiX ABI。


**代码标记规范（已实施）**：

所有高冲突文件中的个人功能代码已用统一标记包裹：

`c
/* === CyclesPlus: <功能名称> <位置说明> Begin === */
// 个人功能实现
/* === CyclesPlus: <功能名称> <位置说明> End === */
`

**标记用途**：
1. **合并官方更新时**：快速定位个人修改边界，避免冲突时误删
2. **添加新功能时**：参考现有标记格式，保持统一
3. **代码审查时**：清晰区分官方代码和个人代码
4. **回退功能时**：精确移除某个功能的所有相关代码

**标记维护规则**：
- 新增个人功能必须添加对应标记
- 标记名称使用英文，格式：<Feature> <Location>
- Begin/End 必须成对出现
- 不在标记内添加嵌套标记

### 4.3 功能开关

个人功能保持独立开关：

```text
WITH_DLSS
use_photon_caustics
use_photon_volume_caustics
photon_casters_selected
photon_caustics_intensity
```

官方默认行为必须在关闭个人开关时保持可用。新增开关应同时具备：

- 默认值。
- UI 显示或明确的内部开关说明。
- CPU、CUDA、OptiX 至少一条安全路径。
- 场景变更后的缓存失效逻辑。

## 5. 官方补丁同步流程

### 5.1 同步前

```text
1. 确认当前分支和提交号。
2. 检查 git status，确认源码改动已经提交。
3. 创建源码备份目录。
4. 创建 sync/blender-版本 分支。
5. 拉取官方标签或官方提交。
6. 生成官方版本差异清单。
```

工作树存在未提交源码时暂停同步，避免把实验改动混入官方补丁。

### 5.2 选择补丁

官方更新分三类处理：

| 类型 | 处理方式 |
| --- | --- |
| 与焦散、光子差分、GPU 内核直接相关 | 优先逐段移植并编译验证 |
| 影响 Cycles 公共数据结构或调度 | 先做 ABI 和性能检查，再移植 |
| 与当前功能无关的 UI、VSE、动画等修复 | 按需求选择，不强制整包合并 |

官方版本升级不等于所有提交都必须一次性导入。每个补丁都要保留官方提交号和来源。
**冲突解决时使用标记**：

当官方补丁修改了已标记的高冲突文件时：

1. **查看冲突范围**：
   ```bash
   git diff --conflict=diff3 <文件名>
   ```

2. **识别标记边界**：
   - 冲突在 `=== CyclesPlus` 标记内 → 保留个人代码
   - 冲突在标记外 → 优先接受官方改动
   - 冲突跨标记边界 → 手动合并，确保标记完整

3. **验证标记完整性**：
   ```bash
   rg "=== CyclesPlus" <文件名> -n
   ```
   确保 Begin/End 仍然配对


### 5.3 同步提交顺序

每次同步固定拆成以下提交：

```text
Sync official Blender X.Y.Z fixes
Adapt CyclesPlus to Blender X.Y.Z
Rebuild CUDA and OptiX kernels for Blender X.Y.Z
Validate caustics, volume caustics and DLSS
```

发现问题时按提交回退，避免回退整条历史。

## 6. 官方和个人代码的冲突优先级

发生冲突时按以下顺序判断：

1. 保留官方安全修复、崩溃修复和内存生命周期修复。
2. 保留官方 GPU 对齐、驱动兼容和内核 ABI 修复。
3. 保留个人功能所需的最小接入点。
4. 个人性能优化与官方调度发生冲突时，先保留正确性，再重新测量性能。
5. 仅凭旧版本截图或主观观感不决定合并结果。

焦散相关的物理表现、能量、噪声和速度必须通过固定场景重新验证。

## 7. 固定回归场景

每次官方同步或个人功能修改后，至少验证以下场景：

### 表面焦散

- 平直、均匀厚度的矩形玻璃板。
- 带倒角的玻璃板。
- 透镜。
- 猴头平滑着色模型。
- 矩形玻璃板和透镜重叠。
- 0° 面光和非零扩散面光。

### 体积焦散

- 单独体积节点。
- 纹理控制密度的体积。
- 玻璃或透镜进入体积后的光束。
- 镜头玻璃挡在相机前。
- 体积边界前后移动光源。
- 低采样和满采样结果。

### 色散

- 玻璃本体可见色散。
- 地面焦散中的色散。
- 体积光束中的色散。
- 自定义色散节点与默认玻璃的对照。

### DLSS 和设备

- DLSS 开启、关闭和切换质量档位。
- NGX 日志写入 `portable/cache`。
- 控制台不持续刷 NGX 初始化信息。
- RTX 20、30、40、50 系列内核加载。
- CUDA、OptiX 内核均可启动。

## 8. 性能验证规则

性能比较使用固定 F12 分辨率和固定工程文件：

```text
相同工程
相同分辨率
相同采样数
相同光子数和 Detail
相同设备
相同颜色管理
相同灯光和相机位置
```

每次只改变一个变量。日志需记录：

- 总渲染时间。
- `integrator_shade_volume` 时间。
- 光子生成和光子上传时间。
- 光束 BVH 构建和查询时间。
- 视口首帧和满采样时间。
- 显存占用和是否发生冻结。

没有新日志时，不宣称性能提升。视口测试和 F12 测试分别记录，不能互相替代。

### 9.2 安装前检查

```text
1. 关闭所有 Blender 进程。
2. 检查 blender.exe 是否被占用。
3. 确认目标安装目录不是个人工程目录。
```

发布包必须从干净安装目录生成，排除个人工程、配置、缓存、测试图片和调试日志。

## 10. 备份、标签与回退

每次新增功能或同步官方版本前创建：

```text
backup/pre_<topic>_<timestamp>/
```

完成并验证后创建标签：

```text
v5.2.1-shuimeng-caustics-YYYYMMDD
```

回退顺序：

1. 关闭 Blender。
2. 保留当前日志和测试结果。
3. 回退到上一个已验证标签。
4. 清理对应构建目录中的过期内核。
5. 重新编译并安装。
6. 使用同一固定场景确认回退成功。

不使用破坏性强制回退覆盖用户未确认的源码和工程文件。

## 12. 版本发布规则

个人版本号使用官方版本加个人后缀：

```text

```

Release 页面至少包含：

## 13. 执行准则

```text

```

后续所有 Blender 官方更新、外部 DLSS/OptiX 更新和个人焦散改动，均按照本规划执行。
