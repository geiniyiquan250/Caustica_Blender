> 更新时间：2026-09-10 23:20

## 建议来源总结

外部专家建议采用三个架构原则实现「未来合并零痛苦」：

1. **核心逻辑外挂化**：独立文件存放算法，官方文件只留 2-3 行挂钩
2. **统一编译宏控制**：使用 `#ifdef WITH_CYCLES_SPPM_CAUSTICS` 包裹所有修改
3. **启用 Git Rerere**：自动记住冲突解决方案


## 外部建议分析总结

### 建议合理性评估 ✅

外部专家的三项建议**完全合理且实用**，是业界管理下游分支的成熟实践：

1. **核心逻辑外挂化**：通过减少官方文件内的代码行数（从数十行降到 2-3 行），将冲突面积缩小 90% 以上
2. **统一编译宏控制**：提供 A/B 测试能力，快速定位问题来源（官方 Bug vs 个人功能 Bug）

这三项建议相互配合，可将官方更新合并时间从 **2-3 小时降至 10-20 分钟**。

## 改进方案

### 方案 1：外挂化大块代码

**原则**：官方文件只留 2-3 行挂钩，算法移到独立文件

**示例**：shade_surface.h 改进

改进前（35 行嵌入）：
```c
/* === CyclesPlus: Photon Hitpoint Writer Begin === */
if (kernel_data.integrator.use_photon_caustics && ...) {
  /* 30 行算法代码 */
}
/* === CyclesPlus: Photon Hitpoint Writer End === */
```

改进后（2 行挂钩）：
```c
#ifdef WITH_CYCLES_SPPM_CAUSTICS
if (kernel_data.integrator.use_photon_caustics) {
  sppm_record_hitpoint(kg, state, &sd, render_buffer);
}
#endif
```

独立文件 `sppm_hitpoint.h`：
```c
ccl_device_inline void sppm_record_hitpoint(
    KernelGlobals kg,
    IntegratorState state,
    ccl_private ShaderData *sd,
    ccl_global float *render_buffer)
{
  /* 原来的 30 行算法全部移到这里 */
}
```

### 方案 2：添加编译宏开关

在 `CMakeLists.txt` 中添加：
```cmake
option(WITH_CYCLES_SPPM_CAUSTICS \"Enable SPPM photon caustics\" ON)
if(WITH_CYCLES_SPPM_CAUSTICS)
  add_definitions(-DWITH_CYCLES_SPPM_CAUSTICS)
endif()
```

用宏包裹所有个人修改：
```c
#ifdef WITH_CYCLES_SPPM_CAUSTICS
  /* 你的代码 */
#endif
```

好处：
- 编译时 `cmake -DWITH_CYCLES_SPPM_CAUSTICS=OFF` 即可切回官方版本
- A/B 对比测试
- Bug 快速定位

### 方案 3：启用 Git Rerere

```bash
git config --global rerere.enabled true
```

原理：Git 会记住你如何解决某个冲突，下次遇到相同冲突时自动套用

> ❌ 标记 100 行算法代码嵌在官方函数里 → 高冲突

> ✅ 标记 2 行挂钩调用独立文件 → 几乎零冲突

**建议**：
- 保持当前标记方案（不改成补丁）
- 但逐步把标记内的**大块代码**移到独立文件
- 官方文件只留**极短挂钩**

这样既保留了标记的可见性，又获得了外挂化的低冲突优势。
